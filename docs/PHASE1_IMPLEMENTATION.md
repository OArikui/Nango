# Nango-neo Phase 1 実装記録

更新日: 2026-10-09（v2.0.0 時点の記録。2026-10-13 の v2.8.0 で参照先のみ更新）

> この文書は Phase 1 を実装した時点の記録です。その後のバージョンごとの変更は [neo-versions.md](neo-versions.md)、現行のデータ形式は [DT-FMT.md](DT-FMT.md) を参照してください。

## 概要

Phase 1 のブラウザー辞書機能を、`DTformats.neo.v5.12` として定義されたデータ形式を基準に実装した（その後 v5.16 まで更新。[neo-versions.md](neo-versions.md) 参照）。ブラウザー側の内部処理では単語配列を使うが、LocalStorage・インポート・エクスポートの境界で DT-FMT のドキュメント形式に変換する。

## v5.12形式

- `words` は配列ではなく、単語表示名をキーとするオブジェクト。
- `word` / `word(any)` を各単語内に重複保存しない。
- 各単語は1件以上の `meanings` を持つ。
- 各意味には空でない `definition` が必要。
- `fieldTag`、`examples`、`synonyms`、`other_tags` は文字列配列。`fieldTag` は1要素につき1つの分野タグを格納し、中点で複数タグを連結しない。
- `datetime` は RFC 3339日時文字列。
- `additional_data` は文字列配列。
- 過去形式の必須キー末尾 `$` はインポート時に除去し、標準の必須項目チェックを行う。

当時のスキーマ・AI向けひな形・データ例は `Nango-neo/DTformats.neo.v5.16/` にあり、現行形式は [DT-FMT.md](DT-FMT.md) を参照（[DT-FMT.md](DT-FMT.md)）。

## Phase 1 機能

### データ取り込み・形式

- v5.12形式を正規形式として読込・保存・エクスポート。
- 旧版の単語配列や単一 `meaning` 形式を読み込み、複数 `meanings` 形式へ移行。
- HTMLからJavaScriptを読み込む設定を追加。
- 必須の `meanings` / `definition`、日付文字列、リスト項目型などを検証。
- 起動時に既存のLocalStorageデータをv5.12形式へ変換して保存。
- 登録時・インポート時に登録順のIDを採番。追加入力では既存IDを維持し、新しい単語だけ末尾のIDを割り当てる。
- 複数JSONファイルをまとめて読み、すべてのファイルを検証してから変更を適用する。いずれかが不正なら取り込み全体を中止する。

### 重複処理

- 表示名と、括弧内表記に基づいて同じ単語を検出。
- タグ・例文・類義語などのリスト型項目は重複を除いて自動マージ。
- 定義が異なる意味は別の意味として追加。
- 同じ定義に対する背景・ニュアンスなどの競合は確認ダイアログで採用値を選択。
- 同じ辞書内に表示名が重複し、エクスポート時に一方が上書きされる状態を防止。

### 検索・編集・UX

- 意味、背景、ニュアンス、例文、類義語、複数タグなどを含む全文検索。
- 分類・時代・分野タグでサイドバーを切替表示。分野タグは意味単位で複数設定可能。旧データの `IT・美容・ライフスタイル` のような連結値も、読み込み時に独立したタグへ自動分割。
- 分野タグ・時代タグ・その他タグを一覧表示し、一括改名・削除。
- 意味単位の追加、コピー、貼り付け、複製、削除、順序変更。
- JSON貼り付けによる取り込み。
- 日付に基づいて毎日同じ語を提示する「今日の単語」。
- 画面への単語データ表示時にHTMLエスケープを適用。

## テスト

当時、開発環境で以下を実行し、全項目成功を確認した（現行のテストは [CONTRIBUTING.md](CONTRIBUTING.md) を参照）。

```powershell
node test_or_future/phase1_smoke.test.js
python -m unittest test_or_future.test_phase1_format -v
```

- JavaScript純粋ロジックのスモークテスト: 14 assertions（中点区切りのタグ移行・固有名詞タグの保持を追加）
- JSON Schema Draft 2020-12テスト: 7 tests
- Chromiumブラウザー操作テスト: 新規登録、編集、複数意味、意味コピー・貼り付け、JSONエクスポート、複数JSONインポート、意味の全文検索、「今日の単語」を確認。JavaScriptコンソールエラーなし。

## 制約・次段階

- データの永続化はブラウザーの `localStorage`。ブラウザー・プロファイル・オリジンごとに保存領域が異なり、自動同期しない。
- Phase 1ではPython API、ユーザーアカウント、クラウド保存、PostgreSQL/MySQLなどは実装していない（Phase 2）。
- 旧形式から読み込める一方、エクスポートはv5.12形式となる。旧版アプリとデータを往復するときは元データをバックアップすること。

## 分野タグの複数化修正（2026-10-09）

- `fieldTag` の各配列要素を独立したタグとして扱うルールをAI指示・JSON Schemaの説明・テンプレートに明記。
- AI指示では `IT・美容・ライフスタイル` ではなく `["IT", "美容", "ライフスタイル"]` と出力するよう指定。
- アプリの分野タグ入力欄でカンマ・読点・中点・改行を区切りとして利用可能にした。
- 既存データの `fieldTag` に含まれる中点連結値をインポート／読み込み時に分割し、重複を除去。`category` と `other_tags` は中点を含む分類名・固有名詞があり得るため、自動分割しない。
- ユーザー提供の141語データを修正し、151個の連結済み `fieldTag` 値を配列要素に分割。JSON Schema検証に成功。
